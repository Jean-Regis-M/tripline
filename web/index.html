An AI agent will do what the text tells it to.
Tripline decides what it is allowed to do.

Email, web pages and third-party tools can smuggle instructions into an agent. Tripline follows every piece of data from where it was read to where it is about to be sent, and trips the wire before a secret leaves.

Watch an attack get stopped Scan a tool manifest

Three layers, no model trust required

1

Scan before install

Static analysis of MCP tool manifests finds hidden instructions, invisible Unicode, steering of other tools, sensitive file references and data smuggling parameters. A SHA-256 lockfile catches a tool that changes after approval (a rug pull).

2

Track at runtime

Every tool output is labelled private or untrusted. Fragments of private data are fingerprinted, including their base64, hex and URL encodings, so copies are recognised inside later arguments.

3

Decide deterministically

Three small rules run before each outbound call: no private data to unknown destinations, no destinations chosen by untrusted text, and human approval when a session has seen both untrusted input and private data.

      What Tripline does not do

      • It is not a model. The demo agent is scripted. Tripline's guarantees come from the policy layer, and a real model would only change what the agent tries to do.
      • Provenance is fragment based. Exact copies and common encodings are caught. Paraphrased or heavily transformed data is caught only by the session level approval rule, which costs a prompt for the user.
      • Policy needs labels. Tools are labelled by hand or by a name based heuristic. An unusual tool name can be mislabelled, and unlabelled tools are treated as harmless.
      • The scanner is heuristic. It has false negatives. Pair it with pinning and the runtime guard.
