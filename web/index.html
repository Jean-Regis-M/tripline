An agent will do what the text tells it to.

Tripline decides what it is allowed to do. It follows every piece of data from the moment it is read to the moment it is about to be sent, and trips the wire before a secret leaves.

Method

Three layers. None of them asks a model to judge anything.

Scan before install

Static analysis of MCP tool manifests finds hidden instructions, invisible Unicode, steering of other tools, sensitive file references and data smuggling parameters. A SHA-256 lockfile catches a tool that changes after approval, the so called rug pull.

Track at runtime

Every tool output is labelled private or untrusted. Fragments of private data are fingerprinted, including their base64, hex and URL forms, so copies are recognised inside later arguments.

Decide with three rules

No private data to unknown destinations. No destinations chosen by untrusted text. And a session that has seen both untrusted input and private data must get human approval before it sends anything outside.

      05

      Limits

      What Tripline does not do.

      • It is not a model. The demo agent is scripted. Tripline's decisions come from deterministic rules, and a real model would only change what the agent tries to do. This is not a proof of security.
      • Provenance is fragment based. Copies, case and spacing changes, reversal, common encodings and Caesar style ciphers are caught. Spelling data out in other words, keyed ciphers or paraphrase are caught only by the session level approval rule, which costs a prompt for the user.
      • Policy needs labels. Tools are labelled by hand or by a name based heuristic. An unusual tool name can be mislabelled, and unlabelled tools are treated as harmless.
      • The scanner is heuristic. It has false negatives. Pair it with pinning and the runtime guard.
